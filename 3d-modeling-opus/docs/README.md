# 二人のワタナベエイジ展 会場 3D モデル（Opus 版）

大倉公園（大府市）、休憩棟、管理棟、および展示作品（渡辺英司 A01〜A24、渡辺英治 S01〜S16 と付随展示）を Blender で再現したモデルです。
計画・根拠・実装記録は [PLAN.md](PLAN.md)、根拠の要約は [research/](research/) にあります。

## 開き方

- 統合モデル：`out/venue.blend`（Blender 5.2 以降）
- 視点の切り替え：アウトライナーでカメラを選び、テンキー 0 でカメラ視点になります。
  - 巡回カメラ `WALK_park`（公園の入口から休憩棟の玄関まで）、`WALK_rest`（休憩棟の館内）、`WALK_mgmt`（管理棟の館内）。再生すると歩きます。
  - 棟の親 Empty は `REST_root`・`MGMT_root` です。これを選ぶと棟ごとに表示・非表示を切り替えられます。
- 巡回の動画は `out/walk_*.mp4` にあります。

## 歩いて回るビューア（ブラウザ）

`viewer/index.html` をダブルクリックで開きます（file:// のままで動きます。サーバーは要りません）。
画面の構成は旧版（`3d-modeling/viewer/`）と同じです：上の帯に「棟」「視点」「記録写真」「梯子を上る」「玄関に戻る」、中に 3D の画面（左上に場所の札、右上に地図、右下に矢印）、下の帯に「空から」「影」「光」「順路」「操作とモデルについて」。

| 操作 | やり方 |
|---|---|
| 歩く | W A S D・矢印キー、または画面右下の矢印（押している間）。← → は横へ歩く（旧版と同じ） |
| 向きを変える | ドラッグ（離すと止まる）、または ↶ ↷（30° ずつ） |
| 速く歩く | Shift |
| 拡大・縮小 | ホイール（トラックパッドのピンチ）、画面右下の ＋ −、キーの ＋ −（0 で等倍）、スマホは 2 本指でつまむ。約 0.8〜3.4 倍。歩いても倍率を保ち、「視点」を選ぶと等倍 |
| 歩く速さを変える | Shift＋ホイール |
| 棟を移る | 「棟」（公園・休憩棟・管理棟）。選ぶとその入口へ移り、「視点」がその棟の視点になります |
| 決まった視点へ | 「視点」（番号つき、全部で 45） |
| 入口へ戻る | 「玄関に戻る」（いまの棟の入口） |
| その場所へ移動 | 右上の「現在位置と庭・部屋」を開いて地図を押す（棟の中を押すと床に立ちます） |
| 梯子を上る | 休憩棟の樽の梯子の前で W、または「梯子を上る」（上で「梯子を下りる」） |
| 写真と重ねる | 歩き出すと写真を閉じ、写真を撮った位置から歩ける。「記録写真」（合わせ込んだ 48 台のカメラ、棟ごと）。写真はプロジェクトの `files/` から読むので、ビューアだけを別の場所へ移すと写真は出ません。濃さはつまみで変えます。幅 1100 px 未満の画面では出しません。 |
| 空から見る | F キー、または「空から」（E・Space で上、Q で下）。切ると真下の床へ降りる（公園の外の上空では近くの床へ）。梯子の途中と写真の間は切り替えない |
| 影 | 「影」（重くなります） |
| 案内の表示 | 「案内」または H キーで、場所の札・操作の案内・右下のボタン・地図を隠す／出す（作品や景色だけを見るとき）。選んだ状態はブラウザが覚える |
| 光 | 「光」で 昼（晴れ）→ 夕方 → 曇り |
| 順路 | 「順路」でいまの棟の順路を自動で歩く（公園：茅葺門 → 奥の門 → 休憩棟の東玄関、休憩棟・管理棟：館内をひと回り。巡回カメラと同じ経路、1.1 m/s、見どころで 1.5 秒止まる）。キー・ドラッグ・選択で止まる |
| 作品について | 近くに作品があると左上の札に出る。作品名・作者・場所・モデルの大きさと記録写真（撮影位置を解いた写真は「重ねて見る」） |

- 左上の札には、いまいる棟・部屋と、2.5 m 以内の作品（例「S08《蛇の回転錯視》」）を出します。
- 管理棟の S02 の鏡は本物の鏡です（手前の筒は円、鏡の中は六芒星に見えます）。休憩棟の《話す鏡》も同じです。鏡は 12 m 以内にいるときだけ映します。
- 足元は床と地面に沿います。0.45 m までの段は上り、壁や閉じた襖では止まって壁沿いに滑ります。暖簾はくぐれます。
- 葉は Blender で散らした葉の房（約 76 万枚）を同じ位置・形で描きます。近くは全部、遠くは間引いて大きく描きます。軽くするには `index.html?q=low`
- 作り直し：`tools/build_viewer.sh`
  - venue.blend → GLB 3 つ（圧縮なし）＋ nav.json → gzip＋base64 の assets/*.js → esbuild で app.js を作ります（Blender の meshopt 圧縮は座標を丸めて小さな部材が崩れるので使いません）。
- 操作性の検査：`node tools/test_ux.cjs out/ux_test`（Playwright。全視点の選択と歩き出し、ドラッグと離し方、拡大・縮小、地図、写真、順路、梯子、画面の大きさなど。UX OK か UX ISSUES n）
- 自動検査：`node tools/test_viewer.cjs out/viewer_test`
  - Chrome を使い、file:// で次を確かめます。
    - 読み込み
    - 描画速度
    - 休憩棟・管理棟の玄関の段と床の高さ
    - 襖で止まること
    - 地図から跳んだとき床に立つこと
  - 画面の画像を残します。

## 再生成

Blender は Claude のサンドボックスの外で動かします（サンドボックス内では Metal の検出で落ちます）。

```bash
tools/iterate.sh out/iterNN
```

このコマンドは、全体の組み立て、描画、自動検査、写真との照合を続けて実行します。
- `--only rest|mgmt|park`：一部だけを組みます。
- `--filter 正規表現`：描く視点を絞ります。
- `--scale 0.6`：解像度を下げます。

統合モデルだけを作る場合：

```bash
/Applications/Blender.app/Contents/MacOS/Blender -b --factory-startup -P tools/build_all.py -- --out out/venue.blend
```

## 検証の道具

| 道具 | 役割 |
|---|---|
| `tools/verify.py` | 次を自動で確かめます。<br>・作品がすべてあるか<br>・制作者が決めた位置が 1 cm 以内か<br>・作品が壁の面と交差していないか<br>・通路の床が途切れていないか<br>・玄関を通り抜けられるか<br>・巡回カメラの足元に床があり、正面が塞がっていないか<br>・メッシュが健全か |
| `tools/render_views.py` | 写真の校正カメラ、合わせ込んだカメラ、名前付き視点（`spec/views.json`）で描きます。 |
| `tools/compare.py` | 写真と描画を 3 枚並べ（写真｜描画｜エッジの重ね）、エッジ F 値と色差 ΔE を出します。 |
| `tools/photo_edges.py`・`tools/fit_camera.py` | 描画と写真のエッジの距離を最小にするよう、カメラの姿勢を合わせ込みます（Workbench、Nelder–Mead）。<br>・焦点距離は EXIF に固定します。<br>・校正済みのカメラから離れるほど罰則をかけます。<br>合わせた後に残る差が、形の違いを示します。 |
| `tools/render_walk.py` | 巡回カメラの動画を書き出します。 |

## 構成

- `spec/`：生成の入力（park.json、rest.json、management.json、photo_cameras.json、fitted_cameras.json、views.json）
- `tools/vlib.py`：共通部品（壁と開口、屋根、畳、建具、樹木、描画）
- `tools/mats.py`：建物の材質
- `tools/foliage.py`：葉の表現（Geometry Nodes）
- `tools/build_park.py`・`build_rest.py`・`build_mgmt.py`：敷地と二棟
- `tools/exhibits_rest.py`・`exhibits_mgmt.py`：作品と家具
- `tools/walkthrough.py`：巡回カメラ

  - S12（写真提供：渡辺英治）
  - 月の錯視・ログビネンコ錯視
  - 進化ストリーム 3 図（渡辺英治）

## 限界

実測図はありません。休憩棟は畳の寸法から、管理棟は制作者の見取り図（OKURAOBU.pptx）の縮尺から、公園は案内図のアフィン補正から推定しています。
推定で補った部材には、オブジェクトのカスタム属性 `est=1` を付けています。未決事項は PLAN.md §7 を見てください。
