# 二人のワタナベエイジ展 会場 3D 再現 — 実装計画（Opus 版）

2026-09-23 開始。作業ディレクトリ `3d-modeling-opus/`。実装は Claude Opus 5.5。

## 1. 目的と範囲

大倉公園（大府市）で開かれた「二人のワタナベエイジ展」の会場を Blender で再現する。
範囲は次の 4 つ。

1. 大倉公園の敷地：地形、園路、池と水路、茅葺門と奥の門、設営物（暖簾・のぼり・ポスター・説明板）、施設、樹木。
2. 休憩棟：外装（L 字の平面、入母屋と切妻の鋼板屋根、樹皮貼りの外壁、広縁のガラス戸、東の玄関）、間取り 12 区画、内装（畳・板床・聚楽壁・竿縁天井・障子・襖・欄間・床の間）。
3. 管理棟：外装（寄棟 5 棟の屋根、白い外壁）、間取り（OKURAOBU.pptx が正本）、内装、二枚の司壁。
4. 作品：渡辺英司 A01〜A24（休憩棟と屋外）、渡辺英治 S01〜S16 と付随展示 S-X01〜S-X06（管理棟と屋外）。

## 2. 根拠と優先順位

旧モデル `3d-modeling/`（Codex、§1〜§67）の数値を、調査エージェント 4 本が抜き出して `research/` に整理した。

| 資料 | 内容 |
|---|---|
| `research/park.md`・`park_spec.json` | 公園の座標系、二棟の配置、地形関数、園路 24 本、門、樹木 246 本 |
| `research/rest.md`・`rest_spec.json` | 休憩棟の外形・屋根・開口・部屋・建具の開閉・作品・制作者の決定 |
| `research/management.md`・`management_spec.json` | 管理棟の外形・屋根・部屋・司壁・作品・制作者の決定 |
| `research/photos.md`・`photo_cameras.json` | 主要写真の一覧と、校正済みのカメラ |

優先順位は、制作者の訂正 → 旧モデルの後の節 → 旧モデルの実データ → 写真からの推定。
`spec/*.json` は research の JSON を写したもので、生成スクリプトはここだけを読む。
Opus 版での修正は `spec/` を直し、その理由を本書 §8 に記録する。

### 守ること

- **制作者が決めた位置は動かさない**（rest.md §5、management.md §9）。休憩棟の東玄関（X=17.10、Y=10.68）、A02 の位置、R5 の向き、北通路・南廊下の連続、管理棟の PPTX 間取り、司壁 3.44×2.38 m、S02 の見え方（正面は円・鏡では六芒星）、S12 の壁は 3 枚構成、など。
- **画像を貼ってよいのは許可された画像だけ**（ポスター、暖簾・のぼり、休憩棟の写真転写 19 枚、管理棟の 7 枚）。襖絵・第三者の画像は手続き的な表現にとどめる。
- 旧モデルの `3d-modeling/` と公開用の `share/` には書き込まない。

## 3. 構成

```
3d-modeling-opus/
  PLAN.md        本書
  README.md      開き方・再生成・検証の手順
  spec/          生成の入力（park.json, rest.json, management.json）
  research/      調査結果と写真の縮小版
  tools/
    vlib.py          共通部品（材質、壁と開口、屋根、畳、建具、樹木、カメラ、描画）
    geo.py           平面幾何（純 Python）
    build_park.py    公園
    build_rest.py    休憩棟（建築）
    build_mgmt.py    管理棟（建築）
    exhibits_rest.py 休憩棟と屋外の作品（A01〜A24）
    exhibits_mgmt.py 管理棟と屋外の作品（S01〜S16, S-X）
    build_all.py     全体を組んで out/venue.blend に保存
    render_views.py  視点一覧（views.json）と写真の校正カメラで描画
    verify.py        構造の自動検査（Blender 内）
    compare.py       写真と描画の照合（エッジ F 値、色差）
    sheet.py         一覧画像
  out/
    venue.blend      統合モデル（公園＋二棟＋作品）
    iterN/           改良ループ N 回目の描画・比較・検査結果
```

座標は公園の世界座標（+X 東、+Y 北、m）。二棟はそれぞれ親 Empty（`REST_root`、`MGMT_root`）の下にローカル座標で作る。
旧モデルと同じ座標系なので、旧モデルで校正した写真カメラ（棟ローカル座標）をそのまま使える。

## 4. 実装の順序

1. 共通部品 vlib と照合ツール（済）。
2. 公園の骨格（済：地形・園路・池・門・設営物・施設・樹木）。
3. 休憩棟の建築：基礎と束、床、外壁（樹皮貼り＋横桟）、広縁のガラス戸、東面（受付のガラス・戸袋・玄関・ポスター・袖の格子窓）、屋根（西翼入母屋・東翼切妻・下屋・北廊下・玄関下屋）、樋、内部の間仕切り、障子・襖・欄間、床の間、天井、照明。
4. 管理棟の建築：外形、屋根 5 棟、外壁、開口、部屋、二枚の司壁、受付窓、家具。
5. 作品：休憩棟 A01〜A24、管理棟 S01〜S16・S-X01〜06、屋外 A24・S16。
6. 統合と保存（`out/venue.blend`）、視点の描画、検査。
7. 改良ループ（§5）。

## 5. 検証と改良ループ

各回で次を行い、結果を `out/iterN/` に保存する。

1. **構造検査**（`verify.py`、Blender 内で自動）
   - 作品一覧の全項目がモデルにあるか（id ごとのオブジェクト数 > 0）。
   - 制作者が決めた位置が許容差 1 cm 以内か（玄関、A02、A04、A09、A01、S02、司壁など）。
   - 作品が壁や床を貫いていないか（作品の外接箱と壁の外接箱の交差）、床より下に沈んでいないか。
   - 各部屋の床の高さ、天井の高さが仕様どおりか。
   - 面の法線・非多様体・NaN 頂点などのメッシュ健全性。
   - 通路の連続性（歩行経路上の点から床レイキャストが途切れないこと）。
2. **写真照合**（`render_views.py` → `compare.py`）
   - 校正済みカメラのある写真は、同じカメラで描画してエッジ F 値と色差を記録する。
   - 校正のない主要写真は、近い視点を手で置いて目視で比較する。
3. **目視の講評**：一覧画像を見て、写真とのずれを「形・位置・色・細部」に分けて書き出し、次の回で直す。
4. 数値が下がった変更は取り消す。

完成の目安：
- 構造検査がすべて通る。
- 作品 A01〜A24、S01〜S16、S-X01〜S-X06 がすべて置かれ、写真と並べて同じ作品と判別できる。
- 主要写真（休憩棟 10 枚以上、管理棟 10 枚以上、公園 5 枚以上）で、写真と描画を並べたときに、部屋・建具・作品の配置が一致する。
- 全体モデルが Blender で開け、各棟の中を歩いて見渡せる（巡回カメラ）。

### 追加依頼：歩いて回るビューア（2026-09-24）

旧 3d-modeling/viewer と同じく、公園と各棟の中を自由に歩けるブラウザのビューアを `viewer/` に作った。

- **書き出し**（tools/export_glb.py）
  - 静的なメッシュをモディファイアごと適用し、区域（park/rest/mgmt）× 当たり判定（solid/soft）で結合した。描画の呼び出しは材質の数まで減る。
  - 材質は代表色の Principled に単純化した。画像テクスチャ（ポスター・許可画像）は残した。
  - meshopt で圧縮した。合計 32 MB。
  - 樹冠の葉は Geometry Nodes のインスタンスが glTF に出ないので、樹冠の位置と大きさ（2,672 個）と葉の 2 色を nav.json に書いた。葉はビューアで InstancedMesh として生成する。
- **ビューア**（three.js r186＋three-mesh-bvh、esbuild で app.js 1 本に）
  - 歩行：床への光線で段 0.45 m まで上る。胸・腰・膝の高さの光線で壁に止まって滑る。
  - 地図：公園と部屋の多角形を描き、押すと移動する。
  - 視点 44 か所。
  - 写真の重ね合わせ：合わせ込んだカメラの焦点距離とシフトを setViewOffset で再現する。
  - 手続き的な模様：木目・畳・聚楽・樹皮・砂利・舗装・茅・瓦棒。襖の山水と市松はキャンバスに描く。
  - file:// で読めるよう、GLB と nav は base64 の script にした。
- **検査**（tools/test_viewer.cjs、Chrome＋puppeteer-core、file://）：すべて合格。
  - 読み込み 1.4 秒、60 fps。
  - 休憩棟の東玄関：石段 0.03 → 0.16 → 0.34 → 床 0.50、衝立で止まる。
  - 管理棟の玄関から床 0.42 へ入れる。
  - 樽の間の北の襖で止まる。
  - 地図からの移動で屋根ではなく床に立つ。
- **直した不具合**
  - 画像のパスが .blend の相対パスで、複製すると外れた。→ 画像を .blend に詰めるようにした。
  - 評価済みの依存グラフが古いまま使われ、Blender が落ちた。
  - 屋根・天井・生垣・草の上に立ってしまった。→ 材質名で除外した。
  - 同じ高さに重なった面のため、空きの判定を誤った。
  - 画像の板が裏打ちと z ファイティングした。→ polygonOffset で手前に描く。
  - 管理棟の基礎が玄関の土間を埋めていた。
  - S16 の草むらを当たり判定から外した。

### 樽の中を写真 6143 に合わせる（iter18、2026-09-24）

`out/progress/6_ladder.jpg` で見比べると、飛行機が大きすぎて固まり、内張りは鈍い青、底が深すぎた。

- **6143 のカメラ**：中身は飛行機と針金ばかりで、エッジ合わせは使えない。代わりに写真から姿勢を解いた。
  - 手がかりは 2 つ。板の縦線が集まる点（真下の方向、1400 幅で (720, 830)。y=60 と 120 の暗い線 11 本から）と、底の楕円の 14 点。
  - これを半径 0.985 の円に合わせた（TS-E17、シフトも未知数。残差 19 px）。
  - 結果：カメラは中心の南 0.76 m（縁の内側）、底の 1.81 m 上。鉛直から 20° 北へ傾け、シフトは (−0.017, 0.076)。
  - 縁は画面の外に出て、手前の内壁だけが下端に写る。写真と同じ見え方になる。
  - `spec/fitted_cameras.json` の 6143（kind_init "ellipse"）と、視点 rest_A04_ladder_top に入れた。
  - render_views.py は、視点の shift_xy も使うようにした。
- **上げ底（est）**：樽は高さ 2.19、天井は 2.61 なので、カメラは床から 2.40 あたりに構えたことになる。そこから 1.81 下なので、底を床から **0.60** にした。
  - シフトを入れない解（底 0.85〜1.0）は、カメラが樽の外に出て縁が写るので捨てた。
- **飛行機**：約 150 機、翼幅 0.08〜0.12 m（底の楕円 1.97 m が 710 px という比から）。
  - 範囲は r0.90 以内、高さは底から 0.05〜0.65。
  - 尖った機首・後退翼・水平尾翼・垂直尾翼の形にした。
  - 45% は白地に差し色、残りは赤・黄・青・濃緑・橙・淡い青灰・桃の単色。

### カメラ合わせの約束

- 焦点距離は EXIF に固定する（TS-E17 は 17 mm）。画角で形の違いを吸収させない。
- 旧モデルで校正済みのカメラから始めるときは、離れるほど罰則（位置 0.3 m・角度 4° で 1 px 相当）。手置きや見比べ用の視点から始めるときは罰則を弱くする。
- 旧カメラが部屋の外にある（6467）など構図が合わない写真は、写真の左右に写るものから初期の位置を手で置き、そこから合わせる（spec/fitted_cameras.json の manual_init）。

### 判断の記録

- **Blender 5.2 の API の変化**：Geometry Nodes のモディファイア入力は `modifier.properties.inputs.<識別子>.value` で設定する（`mod["Socket_1"]` は使えない）。物体を入力に渡せないので、葉の種類ごとに節グループを分けた。
- **照明**：写真はカメラのホワイトバランスで空の青を打ち消しているので、描画でも AgX＋白色の基準 7000K とし、空の色の彩度を 0.5 に下げた。これで畳と聚楽壁の色が写真に近づいた。
- **R5（人工芝の間）の壁**：旧モデルの記述は白だったが、写真 6167 は黄土色の聚楽なので聚楽にした。
- **R5 の西の外側帯**：写真 6167 で R5 の西窓の外に木が見えるので、外壁 X=0 のこの区間をガラスの縁と推定した（est=1）。
- **S14 の奥まり**：仕様の x2.40–4.02 は北の小突出の西壁 x2.56 にかかる。奥まりの幅は仕様のまま、外壁のその区間を開けた。
- **庭木の位置**：旧モデルの幹の位置のうち、休憩棟の外形に入る 1 本は東面の前（ローカル X=17.9）へ出した（写真 6412 の受付ガラス前の木）。
- **樹皮の色**：旧 §38 の茶色 (0.19, 0.14, 0.085) は描画で白っぽく見えたので、茶色のまま暗く (0.11, 0.08, 0.05) にした。

### 9.7 操作の不整合の修正（iter29、2026-09-24、制作者の指摘「操作に不整合な応答がいくつかあり、バグがあるようだ」）
実際のキー・マウスの入力で再現してから直した（scratchpad の bugs.cjs → test_viewer.cjs の「操作の一貫性」に移した）。
1. 「空から」などをマウスで押すとボタンにフォーカスが残り、Space（上昇）でボタンが押し直されて空からが切れた → マウスで押したボタンはフォーカスを外す。Space も動くキーとして扱う。
2. 矢印キーの ← → は向きを変え、画面の ← → は横へ歩いた（旧版はどちらも横へ）→ どちらも横へ歩く（梯子の上ではキーの ← → で向きを変える）。
3. 写真を重ねている間に W・矢印を押しても何も起きなかった（ドラッグだけ写真を閉じた）→ 動くキー・画面の矢印でも写真を閉じる。
4. 写真を閉じると元の場所へ飛び戻った → 写真を撮った位置の床に立って歩き出す（床がなければ元の場所）。
5. 高い所で空からを切ると空中で止まり、動けなくなった（床が 20 m より下にあると床を探せない）→ 真下の立てる床へ降りる。なければ近い順に 200 m まで探して降りる。
6. 空からのまま地図で移動すると、床の高さを飛んだまま（壁を抜けた）→ 地図の移動・順路の開始・写真を閉じるときは歩きに戻す。
7. 視点の画角（例 36.6°）が歩き出しても戻らなかった → 歩き出す・地図で移動する・梯子を上ると 62° へなめらかに戻す。
8. 梯子の途中で F を押すと、下りたあと空からのままだった → 梯子の途中と写真の間は F を効かせない。
9. 同じ視点を選び直しても動かなかった（選択欄は同じ項目では変更を知らせない）→ 選んだ視点から 1.5 m 離れたら選択を外す。

## 13. 各棟の間取りと内装を実測の外形に合わせて作り直す（iter47〜、2026-10-01、制作者の /goal）

制作者の指示：「外容は整ったので、各棟の間取りと内装を作り直すためのプラン、実装、修正の自動ループを実測と整合性が取れるまで回して」。

### 13.1 何を「実測と整合」とみるか
外形（§11・§12）は実測に合わせた。内側は、その外形と次の点で矛盾しないこと：
1. **部屋で外形を埋める**：spec の部屋の多角形の和が、壁の内側（外形）をすき間なく覆い、部屋どうしが重ならず、外形の外に出ない。
   - 基準：覆えていない所 ≤ 外形の 3%（壁の厚み分）、重なり ≤ 0.5 m²、外へのはみ出し ≤ 0.5 m²。
2. **組んだモデルの床と天井**：外形の内側のどこでも、床（土間を含む）と天井がある。外形の外に床・天井がない。
   - `tools/interior_audit.py`（Blender）で外形の 0.1 m 格子からレイを飛ばして測る。
   - 基準：床 ≥ 98%・天井 ≥ 97%（壁の上は除く）、外へのはみ出し 0。
3. **外壁が閉じている**：外形の各辺に外壁（または建具）がある。開いたすき間 ≤ 0.3 m（戸口は除く）。
4. **部屋の寸法**：畳の部屋は畳の数×1.82×0.91（±3 cm）。合板の壁は 0.91 の割付。
5. **登録・市の説明と整合**：
   - 休憩棟：座敷を矩折れに配し、庭側に縁、中央に配膳室。
   - 管理棟：玄関の正面が広間、右が事務室、左が和室、奥が洋室。和室 10 畳・茶室 6 畳・集会室。
6. **写真**：照合表（check_all）を保つ。制作者が決めた位置（rest §5・mgmt §9）は動かさない。

### 13.2 手順
1. spec の部屋を外形に合わせて直す（外形の写し漏れ、重なり、名前のない所）。
2. `interior_audit.py` で床・天井・外壁のすき間を測る。
3. すき間を埋める：新しい部屋（休憩棟 RN・RS、管理棟の北の小棟）の床・天井・内壁・建具。内装は推定で、写真のある部屋の作りに揃える。
4. 2 に戻り、基準を満たすまで繰り返す。最後に check_all・park_check。

## 14. ビューアの操作の欠陥と操作感（iter48、2026-10-01、制作者の /goal）
指示：「ビューワーの操作が欠陥があるので原因を調べて、修正ループを回して、また、操作UIが以前のと変わってしまったので、前バージョンと同じような操作感になるように調整して」。

### 14.1 原因
前の公開版（share 212f9d8）とビューアのコード（app.js）は同一。違いは §10 で公園を実測の配置に替えたことによる座標のずれ。
1. 始めの位置が旧の案内図の座標 (10.7, 86.5) の書き込みのまま → 公園の外の宙から始まり、床がないので歩けない（公開版の画面で確かめた）。
2. 公園の地図の中心と縮尺が旧の固定値（cx −3・cy −5・高さ 190 m）→ 公園が地図の片側に寄る。test_ux の地図の検査も同じ固定値で、休憩棟を押せなかった。
3. 「流れ」の視点 (33, −36.5) が流れの南で公園の外 → 床がなく四方とも動けない。
4. 石の道の両側の生垣が道の終わりまで続き、休憩棟の東の玄関の前の砂利に入り込んだ → 「東側の正式な玄関」（休憩棟の玄関に戻る先）が生垣に囲まれ、四方とも動けない。

### 14.2 修正
- 始めの位置は案内データの「茅葺門の前」の視点（gotoView）。地図は外周の外接矩形が収まる中心・縮尺。
- 地図に広場・周回路（土）、流れ、トイレ・東屋・行者堂を足した（旧の地図に近い描き込み）。地図のクリックは指した所から 1 m 以内に立つ。
- 「流れ」の視点を北岸 (36, −27) へ。park_views.py は地上の視点が外周の外なら止まる。
- 石の道の生垣は道の終わりから 3.5 m を空ける（build_park.py）。
- 操作（WASD・矢印は前後と横歩き、ドラッグ、↶↷ 30°、拡大、Shift＋ホイールの速さ）は変えない：§9 で旧版（3d-modeling）にそろえ、§9.7〜9.9 で制作者の指摘を受けて直した形を保つ。
